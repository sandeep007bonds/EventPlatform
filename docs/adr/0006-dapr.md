# ADR-0006 — Infrastructure abstraction: Dapr

- **Status:** Accepted
- **Date:** 2026-07-23

## Context

Services need pub/sub, state, secrets, service-to-service invocation, and durable
workflow. We want consistent, testable infrastructure access and to avoid
scattering vendor SDKs through domain code. MassTransit v9 moving to a commercial
license reduced the appeal of the usual .NET bus/saga library.

## Decision

Adopt **Dapr** (managed Dapr extension on AKS) as the infrastructure abstraction:
pub/sub, state store, secrets, service invocation, and **Dapr Workflow** for the
orchestrated checkout saga.

## Consequences

- App code talks to the Dapr sidecar (HTTP/gRPC), not Azure SDKs — a clean
  anti-corruption boundary and easy local testing.
- Provider swaps (e.g., Service Bus configuration) are component YAML changes,
  not code.
- CNCF / open source — no per-seat licensing (unlike MassTransit v9 /
  NServiceBus).
- Adds the sidecar model and a learning curve; accepted for the decoupling and
  testability benefits.

## Alternatives considered

- **MassTransit** — great developer experience but v9 is commercially licensed
  now. Rejected to avoid cost/lock-in.
- **NServiceBus** — commercial. Rejected.
- **Raw Azure SDKs + a thin abstraction** — viable, but more bespoke code and
  weaker portability/testability. Rejected.
